# Estado y pasos de publicación

El código y los textos están preparados. Los enlaces de publicaciones solo se registran cuando existan y se hayan verificado.

1. GitHub: crear `sqlite-backup-lab` público en la cuenta autenticada; subir el proyecto completo a `main`, incluido el flujo oculto `.github/workflows/pages.yml`.
2. Settings → Pages → Source: GitHub Actions. Ejecutar el flujo y verificar que las pruebas y despliegue terminen correctamente. Abrir la URL devuelta por el despliegue.
3. Dev.to: iniciar sesión, copiar el artículo sin su bloque de metadatos si se usa el editor visual, añadir enlaces verificados y publicar. Comprobar la URL pública. También sirve Medium o Hashnode.
4. Video: usar el guion de 4:30 y grabar las tomas. Publicar en una red de video con visibilidad Pública; verificar duración y enlace.
5. Completar ENLACES.txt con cuatro URLs reales. Regenerar entrega-enlaces.zip para la entrega; no enviar una versión con campos pendientes como si estuviera terminada.

El acceso al navegador requiere permisos de control del equipo. Los inicios de sesión, 2FA, CAPTCHA, permisos de cuenta y cargos deben resolverlos o aprobarlos el usuario.

La consigna menciona enviar artículo y video a Telegram. El envío no forma parte de las publicaciones ejecutadas en este proyecto: hace falta identificar el grupo y autorizar el envío directamente.
